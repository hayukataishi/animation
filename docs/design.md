# サイト設計書

## 1. プロジェクト概要
本プロジェクトは、様々なWEBアニメーションやインタラクティブなUIギミック（以下「ギミックアイテム」）を収集・展示するポートフォリオサイトである。訪問者はメニューからアイテムを選択し、メイン画面で実際に動作を確認できる。

## 2. 基本コンセプトと用語

### 2.1 ギミックアイテム (Gimmick Item)
- サイトで展示する個々のアニメーションやコンポーネントの単位。
- 各アイテムは独立した動作を持つ。

### 2.2 対応デバイスラベル
各ギミックアイテムには、推奨される閲覧環境や対応状況を示すラベルが付与される。
- **PC**: デスクトップ/ラップトップ環境での閲覧・操作に対応。
- **Phone**: スマートフォンなどのモバイル環境での閲覧・操作に対応。
※ 両方のラベルを持つ場合もある。

## 3. 機能要件

### 3.1 メイン画面 (Main View)
- 選択されたギミックアイテムを表示する中央領域。
- アイテムが選択されていない初期状態では、サイトのイントロダクションまたはデフォルトのビジュアルを表示する。
- 画面遷移を伴わず（あるいはシームレスに）、コンポーネントが切り替わる体験を提供する。

### 3.2 ナビゲーションメニュー (Menu)
- 全てのギミックアイテムを一覧表示する。
- 各アイテムのリストには以下を表示する：
    - アイテム名
    - 対応デバイスラベル (PC / Phone)
- アイテムをクリック/タップすることで、メイン画面の表示内容を選択したアイテムに切り替える。

## 4. データ構造 (Data Structure)

ギミックアイテムは以下のメタデータを持つ。Astroの **Content Collections** を使用して管理することを想定する。

| フィールド名 | 型 | 説明 |
| --- | --- | --- |
| `id` | string | 一意の識別子（スラッグ） |
| `title` | string | ギミックアイテムの名称 |
| `description`| string | ギミックの簡単な説明 |
| `tags` | string[] | `PC`, `Phone` などの対応デバイスラベル |
| `publishDate`| date | 公開日（並び順などに使用） |
| `component` | string | 実装ファイルのパス（または自動解決） |

## 5. UI/UX 設計方針

### 5.1 レイアウト
- **2カラム構成** (PC閲覧時):
    - 左側（または右側）: ナビゲーションメニュー（固定またはオーバーレイ）
    - 残りの領域: メインビュー
- **モバイル構成**:
    - メインビューを全画面表示。
    - メニューはハンバーガーメニューやドロワーなどで呼び出す形式。

### 5.2 インタラクション
- アイテム切り替え時は、ページ全体のリロードを感じさせないスムーズな遷移を行う（Astro View Transitions の活用）。
- 対応外のデバイスで閲覧している場合（例: PC専用ギミックをスマホで開いた場合）、警告メッセージや代替表示を行うことを検討する。

## 6. 実装アプローチ

### 6.1 技術スタック
- **Framework**: Astro
- **Styling**: Tailwind CSS (推奨) または CSS Modules
- **State Management**: Nano Stores (必要に応じてメニューの状態管理などに使用)

### 6.2 ディレクトリ構造案
```
src/
├── content/
│   └── gimmicks/        # ギミックアイテムの定義 (Markdown/MDX/YAML)
│       ├── item-1.mdx
│       └── item-2.mdx
├── components/
│   ├── GimmickViewer.astro  # ギミックを表示するラッパー
│   ├── Menu.astro           # ナビゲーションメニュー
│   └── gimmicks/            # 実際のギミックコンポーネント群
│       ├── FadeInText.astro
│       └── 3dCard.tsx
├── pages/
│   ├── index.astro          # トップページ
│   └── [slug].astro         # 各ギミックの個別ページ (Dynamic Routes)
└── layouts/
    └── Layout.astro         # 共通レイアウト
```

### 6.3 開発フロー
1. `src/content/config.ts` でコレクションスキーマを定義。
2. レイアウトコンポーネントを作成し、メニューとメインエリアを配置。
3. サンプルのギミックアイテムを作成。
4. 動的ルーティングを設定し、アイテムごとのURLを生成。
